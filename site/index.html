The short version

ChatGPT asks. The server downloads. You click the link.

1. You send a link

You paste a TikTok, YouTube, Instagram, X, Reddit, Vimeo, or direct video URL into ChatGPT.

2. ChatGPT calls a tool

The custom connector exposes download_video. ChatGPT calls it over HTTPS at /mcp.

3. The server does the work

yt-dlp extracts the media, ffmpeg merges audio and video, and the file is stored temporarily.

4. You get a link

ChatGPT shows a clickable URL. You click it and the file downloads from the server.

ChatGPT cannot receive a binary file through an MCP tool. The video never travels through the chat. The temporary download link is the deliverable.

The tools

Three actions ChatGPT can take

download_video

Download a video

Accepts a public URL and an optional quality: 360p, 480p, 720p (default), 1080p, or best.

Returns title, platform, duration, size, filename, and a temporary MP4 link.

download_audio

Extract audio

Downloads the best audio stream and converts it to MP3 at 192 kbps using ffmpeg.

Returns a temporary MP3 link plus the same metadata.

get_video_info

Inspect a video

Reads metadata without downloading: title, uploader, duration, thumbnail, view count, live status, available qualities.

Useful when ChatGPT needs details before choosing a quality.

Request lifecycle

Exactly what happens during a download

  1. ChatGPT sends the URL to the MCP endpoint as a tools/call request.
  2. URL validation runs. Only http and https are allowed. The hostname is resolved, and private, loopback, link-local, reserved, and cloud-metadata addresses are rejected.
  3. Rate limit check. A global sliding window allows 40 downloads per hour by default.
  4. Concurrency check. At most 2 downloads run at once. Extra requests wait briefly, then receive a “server busy” message.
  5. yt-dlp starts as a subprocess with playlists disabled, live streams rejected, a 150 MB cap, and a hard 180-second timeout.
  6. Format selection. The server prefers MP4/H.264/AAC, caps quality at 1080p, and asks yt-dlp to merge separate streams when needed.
  7. ffmpeg merges the selected video and audio into one playable file.
  8. The file is moved into /tmp/video-mcp/<random-token>/<clean-name>.mp4.
  9. A JSON result is returned with a public URL built from Render's RENDER_EXTERNAL_URL.
  10. ChatGPT shows the link. You click it, Render serves the file with an attachment header, and the cleanup loop deletes it after the TTL.
Under the hood

Why it works — and where it breaks

yt-dlp is the engine

yt-dlp supports YouTube, TikTok, Instagram, Facebook, X/Twitter, Reddit, Vimeo, Twitch clips, Dailymotion, Streamable, and hundreds of smaller sites. It extracts the real media stream from a page, handles separate video/audio tracks, and passes them to ffmpeg.

Browser impersonation

The server uses curl-cffi with a Chrome TLS fingerprint. This is what makes TikTok work reliably from a datacenter. It is enabled by default and can be disabled with YTDLP_IMPERSONATE.

Optional cookies and proxy

Login-only content can be handled with YTDLP_COOKIES (Netscape cookies.txt) or COOKIES_FILE. A residential/mobile proxy can be supplied with YTDLP_PROXY. Neither is required for public TikTok or direct MP4 URLs.

Safe by construction

User input is passed as an argument list, never interpolated into a shell. There is no command-injection path through the URL. File names are sanitized, tokens are random, and storage is capped.

Free-tier behavior

The service spins down after about 15 minutes of inactivity. The first request after a pause can take 30–60 seconds while the container starts.

Disk is ephemeral. Downloaded files and their links disappear if the service restarts or spins down. Download and open links promptly.

The Docker image includes Python 3.12, ffmpeg, yt-dlp, curl-cffi, and the MCP SDK. It runs as a non-root user.

ChatGPT setup

Adding the connector

  1. Open ChatGPT → Settings → Connectors → Advanced → Developer mode.
  2. Create a custom connector named Video Downloader.
  3. Set the MCP server URL to https://<service>.onrender.com/mcp.
  4. Choose No authentication.
  5. In a chat, ask: “Download this video: <link>” and open the link ChatGPT returns.
Custom connectors require a ChatGPT plan that supports them. The server must be reachable over public HTTPS — Render provides that automatically.

Security

Public and unauthenticated — by design

What is protected

  • SSRF checks reject private, loopback, link-local, reserved, and metadata addresses.
  • Only http/https URLs are accepted; credentials in URLs are rejected.
  • Random capability tokens make file URLs unguessable.
  • Global rate limit, concurrency limit, size caps, and storage caps.
  • No shell execution of user input.
  • Files expire automatically; a cleanup loop runs every 5 minutes.

What to know

Anyone with the service URL can use it. The global rate limit protects the instance, but it is not per-user.

The initial URL is validated, but yt-dlp follows redirects internally, so a malicious public URL that redirects to an internal address is a residual risk.

For a private deployment, put the service behind an access token or a secret path at the proxy/CDN layer. Never enable ALLOW_PRIVATE_URLS on a public server.

FAQ

Quick answers

Why not just use ChatGPT browsing?

Browsing can read a page, but it cannot run yt-dlp, merge separate audio/video streams with ffmpeg, or hand you a saved media file. The MCP gives ChatGPT an action, not just a view.

Does the video pass through ChatGPT?

No. The server downloads it and returns a link. ChatGPT only sees metadata and the URL.

Is it really “any platform”?

It is “any public content yt-dlp can access from the server’s IP.” That covers a huge number of sites, but not DRM, private, paid, or live content.

Why do links expire?

Files live on ephemeral storage. Expiring capability URLs keep the public service from becoming a permanent file host and protect the free instance.
